# 对话导航展示重设计

状态：用户已选择方案三「轮次目录与详情」，已接入现有扩展。日期：2026-09-07。

## 原文结构与字体统一（2026-09-07）

- 原文预览优先展示真实 h1–h6 / ARIA 标题及 strong / b 加粗重点，保留原顺序和层级缩进；可切换查看原文。没有结构标记时保留普通文本，不生成虚构标题。
- 结构从完整消息 DOM 提取，不受 420 字卡片或 20,000 字搜索文本截断影响。超限时优先保留章节标题，并明确提示精简；纯文本传输、旧版本消息兼容和快照体积上限保持有效。
- 两张图共用导航页头与字体：页面标题 19px、详情标题 17px、正文 14px，统一中文无衬线字体。标题内容仍体现各自范围：当前对话标题 / 当前笔记本标题。
- 摘录节点同步增大布局尺寸，避免字号提升导致自动排列重叠；短侧栏的详情允许滚动，保留可读正文区域。
- 验证：87 项自动测试、TypeScript 检查、生产构建；浏览器验证结构/原文切换、精确摘录和回答定位，以及 320 / 480px 排版。预览为隔离样例，未操作真实对话。

## 已实施的方案三

- 紧凑轮次目录及独立详情区；分别标记预览选择与原文位置。
- 点选轮次只预览，独立定位问题/回答；原文预览支持展开和键盘滚动。
- 每轮读取真实摘录，支持打开单条摘录和整体聚焦；往返保留预览与查询状态。
- 按完整轮次搜索、筛选，保留编号及问答关系；连续角色、缺少回答、消息间隔均不会错误配对。
- 320px 窄侧栏保持字号，使用正常滚动；选项菜单容纳刷新、含摘录筛选与回到原文位置。
- 自动生成的语义摘要不在此次实现范围内；预览清楚标注为原文。

下文保留设计阶段的选型记录，最终采用方向以上述已实施内容为准。

## 目标与推荐方向

用户希望在导航侧栏里直接看清五六轮对话的问题和简洁回答，并明确知道预览、原文定位与摘录查看分别指向什么。

推荐默认采用「轮次时间线」：将一轮问题及其回答作为一个阅读单元，以正常字号展示问题和回答预览。轮次编号及细线表达时间顺序。保留既有「导航 → 对话图 / 摘录图」入口。

这次设计提供三个视觉方向，供比较后选择：轮次时间线、问答对照表、轮次目录与详情。三者是候选方案，不建议同时增加为三个产品模式。

## 当前实现带来的限制

- 问题和回答是两个独立画布节点，分别只有 132px 和 218px 宽；标题为 10.5px，回答预览为 8.5px。缩放会继续减小文字。
- 一轮占 84px，六轮约占 504px，另有顶部工具、底部工具及画布边距。侧栏较矮时无法兼顾全景与可读性。
- 现有标题及预览取自标题、首句和原文片段，不是经过语义理解的回答总结。
- 当前数据只提供页面可见路径，无法还原全部隐藏分支。设计不能画出没有数据依据的关系。

## 推荐方案的内容结构

1. 紧凑顶部：对话标题、轮次数、搜索入口及「跟随原文」。
2. 轮次概览：编号、问题、回答预览，摘录数量放在所属消息或轮次内。
3. 按需详情：选中轮次后显示问题/回答切换、原文预览及明确的定位操作。

每轮问题允许最多两行，回答预览一至两行。短问题与短回答的目标行高为 64–80px。正文保持 14px 左右，问题 14–16px，辅助文字 12px。实际尺寸需在选定方案实施时验证。

初始状态优先展示概览，不预先打开大块详情。以侧栏剩余可用高度决定可见轮数，不能只依据屏幕总高度计算。对于小窗口、用户放大字体或长问题，允许正常纵向滚动，不承诺所有尺寸下六轮都能完整出现，也不自动缩小字号。

## 三个视觉方向的取舍

| 方向 | 展示方式 | 适用情况 | 代价 |
| --- | --- | --- | --- |
| 轮次时间线（推荐） | 每轮全宽，上问题、下回答，编号细线串联 | 默认窄侧栏，五六轮快速扫读 | 对话很长时需要滚动 |
| 问答对照表 | 每轮一行，左问题、右回答 | 侧栏较宽，强调逐轮对应 | 窄宽度会导致换行增多 |
| 轮次目录与详情 | 上部紧凑总览，下部阅读选中轮次 | 经常在多轮之间回看、检查长回答 | 详情持续占用部分总览高度 |

## 点击与定位规则

- 点选轮次：在侧栏预览该轮，不改变原文页面位置。
- 在详情内切换「问题 / 回答」：只切换预览消息。
- 点击「定位问题原文 / 定位回答原文」：定位明确的消息，成功后更新原文位置标记。
- 点击「摘录 N」：先列出关联摘录；单条可以直接打开，多条明确展示选择或整体聚焦入口。
- 点击「在摘录图查看」：进入对应笔记本的摘录图，并准确聚焦选中的摘录。
- 切换到摘录图后返回：保留原查询、选中轮次及列表滚动位置。

「预览中」用行背景或选中边框表示；「原文位置」用独立小标记表示。二者允许处于不同轮次。用户选取另一轮、搜索或手动滚动时，暂停自动跟随；通过「回到原文位置」恢复，避免界面自己跳走。

## 内容真实性

- 设计稿中的简洁回答使用示例文案，并不代表现有程序已能自动产生这些总结。
- 如果只有原文片段，界面使用「回答预览」或「原文预览」，不将截取片段宣称为总结。
- 可优先提取原文中明确的总结段、结论句或标题；无法可靠提取时展示原文片段，并允许展开。
- 如将来增加语义摘要，需单独定义来源、生成状态、消息更新后的失效规则，以及与原文的核对方式；本设计不隐含添加外部模型服务。
- 对话图的自动预览与用户保存的摘录是两类内容，标签与入口需要分别命名。

## 关系与边界状态

- 普通相邻轮次：以编号及细线表达先后，不用箭头暗示因果或引用。
- 同轮问答：通过共同分组及问/答标签表达对应关系，不需要额外连线。
- 消息带有版本信息：展示「回答版本 2/3」等标记；未读到的版本不画成虚构分支。
- 未来只有获得真实父子关系后才展示分支连线。
- 「仅含摘录」按完整轮次筛选，保留相邻问答上下文；原轮次编号不重排，间隔标注省略轮数。
- 搜索定位匹配消息，并显示所在轮次完整上下文，不把不同轮次的问答拼接为一轮。
- 问题尚无回答、连续回答、角色未知等状态明确显示，不凭位置强行配对。
- 新回答生成时只更新对应轮次，不重置选中项和滚动位置。
- 全部轮次标注为「页面可见路径」，避免暗示已读取整棵对话树。

## 实施后的验收重点

- 六轮标准样本在正常侧栏中可直接扫读；320px、420px、520px 宽及较矮视口中不缩小文字或产生横向拖动依赖。
- 点击预览不滚动原文；点击定位准确对应问题或回答，长回答从开头进入视野。
- 同轮多个摘录可区分并准确打开；返回后保留导航位置。
- 搜索、摘录筛选和版本标记均保留真实轮次关系。
- 键盘可操作所有定位与摘录按钮，焦点可见，选中和原文位置不只通过颜色区分。
